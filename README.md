# TodoLock

일반 할 일(todo) 앱 + **잠금해제하면 오늘의 할 일이 자동으로 뜨는** 기능.
오늘 등록된 할 일이 하나도 없으면 아무것도 뜨지 않습니다.

---

## 소개

할 일 앱을 깔아놓고 **정작 앱을 열지 않아서** 할 일을 잊는 문제를 해결하려고 만든
안드로이드 앱입니다.

> 사람은 하루에 수십 번 휴대폰 잠금을 해제합니다.
> 그 순간이 이미 화면을 보고 있는 유일하게 확실한 시점이므로,
> **할 일을 보러 가는 대신 할 일이 찾아오게** 만들었습니다.

잠금을 해제하면 오늘의 할 일 목록이 화면 위에 바로 떠서, 그 자리에서 체크하고 닫을 수
있습니다. 오늘 할 일이 없거나 이미 다 끝냈으면 아무것도 뜨지 않아서 방해가 되지
않습니다.

**이런 사람에게 맞습니다** — 알림은 무시하게 되지만 잠금해제 순간의 강제 노출은
효과가 있는 분, 서버 계정 없이 폰 안에만 데이터를 두고 싶은 분.
**이런 사람에게는 안 맞습니다** — 여러 기기 동기화, 협업/공유, 반복 일정·캘린더 연동이
필요한 분 (모두 없는 기능입니다).

## 주요 기능

| 기능 | 설명 |
|---|---|
| 잠금해제 시 자동 표시 | 잠금을 푼 직후 오늘의 할 일 팝업이 뜨고, 팝업에서 바로 체크 가능 |
| 조용한 기본 동작 | 오늘 남은 할 일이 없으면 표시 안 함. 팝업에는 완료된 항목을 보여주지 않습니다 |
| 표시 빈도 3단계 | 매번 / 1시간마다 / 하루 1번 — 잠금해제가 잦아도 피곤하지 않게 ([4번 항목](#4-표시-빈도-설정)) |
| 한 화면에 전부 | 날짜별로 갈아타지 않고 모든 할 일이 한 목록에. 메모 아래 작은 날짜가 붙고, 지난 날짜는 `지남` 으로 표시 |
| 한 줄로 끝나는 추가 | 화면 아래에 낮게 뜨는 시트. 첫 줄에 `입력칸 · ★중요 · ＋저장`, 둘째 줄에 `기한 설정 · 미리 알림` |
| 기한 설정 | 셀렉트박스로 `오늘` / `내일 (요일)` / `날짜 선택` → 날짜 선택은 달력. 고르지 않으면 오늘 |
| 미리 알림 | 셀렉트박스로 `내일 (요일) 9시` / `다음 주 (요일) 9시` / `날짜 및 시간 선택` → 달력 다음 시계. 기한과 무관한 절대 시각으로 저장됩니다 |
| 알림에서 바로 완료 | 알림의 `완료` 버튼으로 앱을 열지 않고 처리 |
| 알림 방식 3단계 | `알림창`(조용히 쌓임) / `헤드업`(화면 위에 잠깐, 기본) / `전체 팝업`(화면을 덮는 창). 헤드업·전체 팝업도 알림창에는 항상 남습니다 |
| 날짜 오래된 순 정렬 | 정렬 우선순위는 날짜(오래된 것 먼저) → 중요 → 미리 알림 이른 순 → 등록순 |
| 홈 화면 위젯 | 할 일 목록을 홈에서 바로 보고 처리. `○` 완료 · 본문 수정 · `☆` 중요 · `＋` 추가 · `⚙` 설정 |
| 위젯 설정 | 톱니바퀴에서 불투명도(20~100%)와 글꼴 크기(작게·보통·크게)를 조절 |
| 앱 안 열고 추가 | 위젯의 `＋` 는 홈 화면 위에 입력 시트만 띄웁니다 (앱 전체가 열리지 않음) |
| 완료 섹션 분리 | 체크하면 아래 `완료` 섹션으로 내려감 |
| 권한 없어도 동작 | 오버레이 권한이 없으면 전체화면/헤드업 알림으로 대체 표시 |
| 껐다 켜기 | 스위치 하나로 감지 서비스 전체를 중단 |
| 재부팅 복구 | 재부팅·앱 업데이트 후에도 `BootReceiver` 가 서비스를 자동 재시작 |

## 기술 스택

- **Kotlin** + Android View 시스템 (ViewBinding), Material Components
- **minSdk 24 / targetSdk 34**, Java 17
- 저장소는 **SharedPreferences + JSON** — Room·애노테이션 프로세서 없음
- 외부 라이브러리는 AndroidX / Material 뿐, **네트워크 코드 없음**
- APK는 **GitHub Actions** 에서 빌드해 Releases 로 발행 (로컬에 안드로이드 스튜디오 불필요)

## 개인정보

`INTERNET` 권한이 없습니다. 할 일 데이터는 기기 내부 SharedPreferences에만 저장되며
어디에도 전송되지 않고, 계정·로그인·분석 도구도 없습니다.

## 1. APK 받는 방법 (안드로이드 스튜디오 없이)

1. GitHub에 새 저장소를 만듭니다 (private도 됩니다).
2. 이 폴더 전체를 push 합니다.
   ```bash
   cd TodoLock
   git init && git add -A && git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/<내아이디>/<저장소이름>.git
   git push -u origin main
   ```
3. 저장소의 **Actions** 탭 → `Build APK` 워크플로가 자동 실행됩니다 (약 3~5분).
4. 실행이 끝나면 해당 실행 화면 하단 **Artifacts → TodoLock-apk** 를 다운로드.
   압축을 풀면 `app-debug.apk` 가 나옵니다.
5. 폰으로 옮겨서 설치 (설정에서 "출처를 알 수 없는 앱 설치" 허용 필요).

### 안드로이드 스튜디오로 빌드하는 경우
폴더를 그대로 열고 `Build ▸ Build Bundle(s)/APK(s) ▸ Build APK(s)`.
(Gradle wrapper jar는 포함하지 않았으므로 스튜디오가 자동으로 받아옵니다.)

## 2. 설치 후 필수 설정 ⚠️

앱을 열고 아래를 꼭 해주세요. **특히 첫 번째가 없으면 팝업이 뜨지 않습니다.**

| 항목 | 위치 | 이유 |
|---|---|---|
| **다른 앱 위에 표시** | 앱 하단 `권한 주기` 버튼 | Android 10+ 는 이 권한이 있어야 백그라운드에서 화면을 띄울 수 있습니다 |
| 알림 권한 | 첫 실행 시 자동 요청 | 감지 서비스 유지 + 대체 알림용 |
| 배터리 최적화 예외 | 앱 하단 `배터리 예외` 버튼 | 삼성·샤오미 등에서 서비스가 강제 종료되는 것 방지 |
| 알람 및 리마인더 | 설정 → 앱 → TodoLock → `알람 및 리마인더` (진단의 `✘ 정확한 미리 알림` 으로 확인) | Android 12+ 는 이 권한이 없으면 미리 알림이 몇 분 늦게 울립니다 |

권한이 없으면 팝업 대신 **전체화면/헤드업 알림**으로 대체 표시됩니다(기능은 유지).

## 2-1. 팝업이 안 뜰 때 (문제 해결)

앱 하단 **진단** 영역에 각 관문의 상태(`✔`/`✘`)와 **마지막 잠금해제 감지 시각**이 표시됩니다.
어느 줄이 `✘` 인지 먼저 확인하세요.

| 진단 결과 | 원인과 해결 |
|---|---|
| `✘ 감지 서비스 실행 중` | 절전 기능이 서비스를 죽인 상태. `배터리 예외` 를 허용하세요. 앱을 다시 열면 서비스는 스스로 되살아납니다 |
| `✘ 다른 앱 위에 표시` | 팝업이 불가능한 상태. `권한 주기` 버튼으로 허용 (없으면 알림으로만 표시) |
| `✘ 마지막 브로드캐스트: 아직 없음` 인데 서비스는 `✔` | **가장 흔한 함정.** 화면이 꺼진 동안 앱이 재워져 잠금해제 시점에는 리시버가 없었고, 앱을 여는 순간 자동 복구되어 `✔` 로 보이는 상태입니다. 배터리 예외 설정이 필수이며, 워치독이 15분마다 서비스를 되살립니다 |
| 브로드캐스트는 오는데 감지가 안 됨 | `최근 기록` 에 `SCREEN_ON` 만 있고 `USER_PRESENT` 가 없다면 기기가 해당 브로드캐스트를 주지 않는 경우 — 키가드 감시 경로가 대신 처리합니다 |
| 감지 시각은 갱신되는데 팝업이 안 뜸 | `처리:` 줄에 이유가 표시됩니다 (오늘 할 일 없음 / 빈도 제한 / 권한 없음 등) |

### 삼성(One UI) 추가 설정

삼성은 포그라운드 서비스도 절전 대상으로 넣기 때문에 아래가 필요합니다.

- 설정 → 앱 → TodoLock → **배터리** → **제한 없음**
- 설정 → 배터리 → 기타 배터리 설정 → **사용하지 않는 앱을 절전 상태로 전환** 끄기
- 설정 → 배터리 → 백그라운드 사용 제한 → **절전 모드로 전환하지 않는 앱** → 우측 상단 `+` 로 TodoLock 추가
  (목록에 기본으로 없는 것이 정상입니다. 직접 추가하는 목록이며, One UI 버전에 따라 이 메뉴가 없을 수도 있습니다. 위의 `제한 없음` 설정으로 대체됩니다.)

앱을 열 때마다 서비스가 죽어 있으면 자동으로 다시 시작하므로, 위 설정이 어렵다면
하루 한 번 앱을 열어주는 것으로도 동작합니다.

## 3. 동작 방식

```
잠금해제
   ├─ ACTION_USER_PRESENT ────────────┐  (정석 경로)
   └─ ACTION_SCREEN_ON → 키가드 감시 ─┤  (USER_PRESENT 가 안 오는 기기 대비)
                                      ↓
UnlockService (포그라운드 서비스, 알림 중요도 MIN → 상태바에 거의 안 보임)
  └─ UnlockReceiver 가 런타임 등록되어 브로드캐스트 수신
                                      ↓
오늘 날짜에 '미완료' 할 일이 있는가?
   ├─ 없음 → 아무것도 안 함
   └─ 있음 → 0.5초 후 TodayPopupActivity 표시
              (overlay 권한 없으면 → 전체화면 인텐트 알림)

Watchdog (AlarmManager, 15분 간격) ─→ 서비스가 죽어 있으면 다시 세움
```

- Android 8+ 부터 `ACTION_USER_PRESENT` 는 매니페스트로 받을 수 없어서,
  포그라운드 서비스가 **런타임에** 리시버를 등록하는 구조입니다.
- 그래서 **서비스가 죽으면 리시버도 함께 사라집니다.** 삼성 등에서 화면이 꺼진 동안
  앱이 재워지면 잠금해제를 놓치게 되므로, `Watchdog` 이 알람으로 프로세스를 깨워
  서비스를 되살립니다. 알람은 앱이 죽어도 시스템에 남아 있어 유일하게 신뢰할 수 있는 경로입니다.
  (권한이 필요한 정확 알람 대신 `setAndAllowWhileIdle` 을 매번 재예약하므로 수 분 오차가 있습니다)
- 재부팅/앱 업데이트 후에는 `BootReceiver` 가 서비스와 알람을 다시 세웁니다.

## 4. 표시 빈도 설정

잠금해제는 하루에 수십 번 하게 되므로 세 가지 모드를 넣었습니다.
- **매번** — 잠금해제할 때마다 (원래 요구사항)
- **1시간마다** — 마지막 표시 후 1시간 지났을 때만
- **하루 1번** — 그날 첫 잠금해제에만

## 5. 파일 구조

```
app/src/main/java/com/example/todolock/
├── MainActivity.kt          할 일 목록/삭제, 추가 시트 호출, 설정, 진단
├── AddTodoSheet.kt          기한 · 미리 알림 · 중요를 고르는 추가/수정 시트 (BottomSheetDialog)
├── QuickAddActivity.kt      위젯에서 앱을 열지 않고 추가·수정하는 투명 액티비티
├── TodoWidget.kt            홈 화면 위젯 (AppWidgetProvider)
├── TodoWidgetService.kt     위젯 목록 행 공급 (RemoteViewsService)
├── WidgetConfig.kt          위젯 불투명도 · 글꼴 크기 설정
├── WidgetSettingsActivity.kt 톱니바퀴로 열리는 위젯 설정
├── MaxHeightScrollView.kt   팝업 목록의 높이 상한 (버튼이 잘리지 않게)
├── ReminderPopupActivity.kt 알림 방식이 '전체 팝업' 일 때 뜨는 창
├── TodayPopupActivity.kt    잠금해제 시 뜨는 팝업
├── UnlockService.kt         잠금해제 감지용 포그라운드 서비스
├── UnlockReceiver.kt        ACTION_USER_PRESENT 처리 + 팝업 실행
├── BootReceiver.kt          재부팅 후 서비스 복구 + 미리 알림 재예약
├── Watchdog.kt              알람으로 프로세스를 깨워 서비스 부활 (절전 대응)
├── Reminders.kt             미리 알림 알람 예약/취소/재예약 (AlarmManager)
├── ReminderReceiver.kt      알림 발생 + 알림의 '완료' 버튼 처리
├── Notifications.kt         알림 채널 / 대체 알림 / 미리 알림
├── TodoStore.kt             SharedPreferences + JSON 저장소, 기한 계산, 정렬, 진단 기록
├── TodoAdapter.kt           '할 일 / 완료' 섹션 헤더 + 행 (뷰 타입 2종)
├── TodoRow.kt / Todo.kt
```

데이터는 SharedPreferences에 JSON으로 저장합니다 (Room·애노테이션 프로세서 없음 → 빌드가 단순하고 빠릅니다).
